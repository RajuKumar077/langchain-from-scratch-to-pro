## 1. Lesson goal

This lesson teaches you how to evaluate an AI application's answers automatically.

Your program has:
- A **dataset** containing questions and reference answers.
- A **Student AI** that generates predictions.
- A **Judge AI** that compares each prediction with the reference answer.
- **LangSmith** to run the experiment and display the evaluation results.

The key idea is to measure answer quality, not just whether the Python code runs.

---

## 2. The three important pieces of information

For each question, keep these three things separate.

| Name | Meaning | Where it comes from |
|---|---|---|
| `question` | The question being asked | Dataset input |
| `reference_answer` | The expected answer used as the comparison standard | Written into the dataset before evaluation |
| `prediction` | The answer generated by the Student AI | Generated at runtime by `target_student_pipeline()` |

The Judge AI then produces an **evaluation result**: a score and a comment explaining its decision.

### Example

**Question:** What is the difference between a Run and a Trace?

**Reference answer:** A Run represents an individual component execution, while a Trace contains the hierarchy of related runs.

**Student AI prediction:** A Run is one operation, while a Trace groups related operations together.

**Judge result:** Score `1.0`, with a comment saying the prediction captures the essential distinction.

The example above is illustrative. The actual score depends on what the model generates and how the judge evaluates it.

### Important distinction

The reference answer is not generated by the Judge AI during the evaluation. It is stored in the dataset. The prediction is generated by the Student AI. The Judge AI generates the score and evaluation comment.

An LLM judge can still make mistakes. Its score is an automated assessment, not guaranteed truth.

## 5. Function 1: `get_or_create_dataset(client)`

### Purpose

Find the dataset in LangSmith, or create it with questions and reference answers if it does not exist.

Think of this function as preparing the exam paper and answer key before the exam begins.

### Main steps

1. Check whether `DATASET_NAME` already exists using `client.has_dataset(...)`.
2. If it exists, retrieve it using `client.read_dataset(...)`.
3. If it does not exist, create a dataset with a description.
4. Add the question-and-reference-answer examples.
5. Return the dataset so the rest of the program can use it.

### Dataset examples in this lesson

The code adds two questions:

1. **Run vs Trace:** the reference answer explains that a Run is an individual execution, while a Trace represents the hierarchy of related runs.
2. **Annotation Queue:** the reference answer explains that an Annotation Queue helps human reviewers inspect and label selected runs or traces for quality review.

### Why does this matter?

The evaluator needs a comparison standard. Without reference answers, this particular rubric would not have the expected answer against which to assess the prediction.

### Key names to recognize

- `client.has_dataset(...)`: checks whether the dataset exists.
- `client.read_dataset(...)`: retrieves an existing dataset.
- `client.create_dataset(...)`: creates a new dataset.
- `client.create_example(...)` or the corresponding example-creation call in your code: adds a question and its expected answer.

**Remember:** the reference answers are prepared in the dataset; they are not created by the Student AI or the Judge AI during each evaluation run.

## 6. Function 2: `target_student_pipeline(inputs: dict)`

### Purpose

Answer the dataset question using the Student AI. LangSmith calls this function for each dataset example during the experiment.

Think of it as the student taking the exam.

### Step 1: Read the question

```python
question = inputs["question"]
```

`inputs` is a dictionary containing the input fields for the example. This line retrieves the question.

### Step 2: Initialize the local model

```python
llm = ChatOllama(
    model=os.getenv("OLLAMA_MODEL", "qwen3:8b"),
    temperature=0.2
)
```

This creates a connection to the local Ollama model.

The Student AI uses `temperature=0.2`, which generally encourages more consistent output than a high temperature, while still allowing some variation.

### Step 3: Create the answer prompt

The `ChatPromptTemplate` tells the Student AI to answer accurately and concisely in about two or three sentences.

A prompt template is an instruction pattern. The actual question is inserted when the chain is invoked.

### Step 4: Connect the chain

```python
chain = prompt | llm | StrOutputParser()
```

Read the `|` symbol as “then”:

1. `prompt`: prepares the messages for the model.
2. `llm`: generates the answer.
3. `StrOutputParser()`: returns the response as a string.

This is LangChain Expression Language (LCEL) syntax.

### Step 5: Generate the prediction

```python
answer = chain.invoke({"question": question})
```

This sends the question through the chain and waits for the model's response.

### Step 6: Return the prediction

```python
return {"prediction": answer}
```

The result is a dictionary. The key `prediction` is important because the evaluator later reads the model's answer using that same key.

### Input and output

**Input:**

```python
{"question": "What is the difference between a Run and a Trace?"}
```

**Output shape:**

```python
{"prediction": "A Run represents an individual execution, while a Trace groups related runs."}
```

The output shown here is only an example.

### Key takeaway

`target_student_pipeline()` generates the answer. It does not decide whether the answer is correct.

## 7. Function 3: `llm_judge_factual_accuracy(run: Run, example: Example)`

### Purpose

Use a second LLM call as a judge to compare the Student AI's prediction with the dataset's reference answer.

This is the evaluator function. It is passed to LangSmith through the `evaluators` argument in `evaluate(...)`.

### Step 1: Read the question

```python
question = example.inputs["question"]
```

`example` is the dataset example. Its `inputs` contain the original question.

### Step 2: Read the reference answer

```python
reference_answer = example.outputs["reference_answer"]
```

This retrieves the expected answer that was saved in the dataset.

### Step 3: Read the Student AI prediction

```python
prediction = run.outputs["prediction"]
```

`run.outputs` contains the output returned by `target_student_pipeline()`. The code reads its `prediction` field.

### The three values at this point

| Variable | Meaning | Source |
|---|---|---|
| `question` | Original question | `example.inputs` |
| `reference_answer` | Expected answer | `example.outputs` |
| `prediction` | Generated answer | `run.outputs` |

This distinction is central to the lesson.

### Step 4: Initialize the Judge AI

```python
judge_llm = ChatOllama(
    model=os.getenv("OLLAMA_MODEL", "qwen3:8b"),
    temperature=0.0
)
```

The code uses Qwen3 again, but now it is acting as the judge.

The judge uses `temperature=0.0` to encourage more consistent decisions. This does not guarantee identical or correct judgments in every situation.

### Step 5: Build the judge prompt

The `judge_prompt` gives the Judge AI:
- The question.
- The reference answer.
- The Student AI prediction.
- The evaluation rubric.

The rubric asks the judge to assess whether the prediction conveys the essential facts in the reference answer and to return JSON containing `reasoning` and `score`.

The code's current scoring rule is **binary**:

- `1.0`: the prediction meets the rubric's factual-accuracy criterion.
- `0.0`: the prediction does not meet the criterion.

Although a score between `0.0` and `1.0` can sound like a gradual scale, this specific rubric only asks for `0.0` or `1.0`.

### Step 6: Connect and invoke the judge chain

```python
judge_chain = judge_prompt | judge_llm | StrOutputParser()
```

As with the Student chain, the prompt is prepared, sent to the model, and parsed into a string.

The judge chain is then invoked with the question, reference answer, and prediction. The result is expected to be JSON text.

### Step 7: Parse the judge response

```python
json.loads(judge_response)
```

`json.loads(...)` converts valid JSON text into a Python dictionary.

For example, a model might return:

```json
{
  "reasoning": "The prediction captures the key distinction.",
  "score": 1.0
}
```

Your code extracts the score and reasoning from that response. It also contains fallback parsing in case the model does not return valid JSON.

Fallback text parsing can be fragile, so inspect unexpected results rather than assuming every response was parsed correctly.

### Step 8: Return an `EvaluationResult`

```python
return EvaluationResult(
    key="llm_factual_accuracy",
    score=score,
    comment=reasoning
)
```

This packages the evaluator's decision in a format LangSmith understands.

- `key`: the name of the evaluation metric.
- `score`: the numeric result.
- `comment`: the judge's explanation.

### Important limitation: the judge is also an LLM

The Judge AI's score and comment are generated by a language model. The reference answer, however, is stored in the dataset before evaluation.

The judge can make a mistake, misunderstand a valid alternative answer, or accept an incorrect reference answer. For important applications, verify reference answers and compare automated evaluations with human-reviewed examples.

### Key takeaway

`llm_judge_factual_accuracy()` does not generate the Student AI answer. It evaluates that answer and returns a score and comment.

## 8. Function 4: `main()`

### Purpose

Coordinate the full process from configuration checks to launching the LangSmith experiment.

Think of `main()` as the exam coordinator.

### Step 1: Check the LangSmith API key

```python
if not os.getenv("LANGCHAIN_API_KEY"):
```

The code checks whether the required environment variable is present. If it is missing, the program should stop or report the configuration problem instead of trying to use LangSmith without credentials.

### Step 2: Create a LangSmith client

```python
client = Client()
```

The client lets the code interact with LangSmith resources, including the dataset.

### Step 3: Prepare the dataset

```python
get_or_create_dataset(client)
```

This ensures that the dataset is available before the experiment starts.

### Step 4: Launch the evaluation

The code calls `evaluate(...)` with arguments similar to:

```python
evaluate(
    target_student_pipeline,
    data=DATASET_NAME,
    evaluators=[llm_judge_factual_accuracy],
    experiment_prefix="local-qwen3-judge-experiment",
    metadata={...}
)
```

What the important arguments mean:

| Argument | Meaning |
|---|---|
| `target_student_pipeline` | Function that generates the predictions. |
| `data=DATASET_NAME` | Dataset containing the questions and reference answers. |
| `evaluators=[llm_judge_factual_accuracy]` | Function LangSmith calls to evaluate each prediction. |
| `experiment_prefix` | Prefix used to identify the experiment in LangSmith. |
| `metadata` | Extra details recorded with the experiment, such as model and evaluator information. |

For each dataset example, the evaluation process runs the Student pipeline, passes the resulting output and dataset example to the evaluator, and records the result.

### Step 5: Print the experiment link

The code prints a LangSmith URL so you can open the experiment and inspect its results.

### Key takeaway

`main()` coordinates the workflow. It does not itself write the reference answers or make the judgment; it calls the functions that do those jobs.
