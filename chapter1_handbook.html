Topic: Why LangChain? ⭐☆☆☆☆

The chapter's sidebar argues for LangChain over using a raw provider SDK directly, citing two concrete reasons from the text:

  • Prebuilt common patterns — reference implementations of chain-of-thought, tool calling, etc., so you don't build them from scratch.
  • Interchangeable building blocks — every component (LLM, chat model, output parser) follows a shared specification, so swapping providers doesn't require rewrites.

The book's own running example components: LLM/chat model: OpenAI, Embeddings: OpenAI, Vector store: PGVector — with suggested swap-outs: Anthropic/Ollama for chat models, Cohere/Ollama for embeddings, Weaviate/OpenSearch for vector stores.

Also mentioned: OpenAI and Anthropic both expose chat APIs with messages (type + content), but their formats are subtly incompatible — LangChain abstracts this so a single conversation could even mix providers. Additional orchestration benefits cited: a shared callbacks system for observability, a shared interface across major components, and the ability to interrupt/resume/retry long-running applications.

Set export OPENAI_API_KEY=your-key, then run jupyter notebook.

npm install @langchain/core pg

Topic: LLM Interface vs. Chat Model Interface ⭐⭐☆☆☆

LangChain provides two simple interfaces to interact with any LLM API provider: LLMs and Chat models.

  • LLM interface: takes a string prompt as input, sends it to the provider, returns the prediction as output. Example: OpenAI(model="gpt-3.5-turbo").
  • Chat model interface: enables back-and-forth conversations; messages are differentiated into system, user, and assistant roles.
    • System role — instructions the model should use to answer a user question.
    • User role — the user's query and other user-produced content.
    • Assistant role — content generated by the model.

Topic: The OpenAI LLM Wrapper & Parameters ⭐⭐☆☆☆

Example from the book:

# Python
from langchain_openai.llms import OpenAI
model = OpenAI(model="gpt-3.5-turbo")
model.invoke("The sky is")
# Output: "Blue!"

Documented parameters (verbatim from the chapter):

ParameterWhat it does
modelThe most common config — which underlying model to use (trade-off of capability vs. cost/speed)
temperatureControls sampling randomness. Lower (e.g. 0.1) = predictable; higher (e.g. 0.9) = creative/unexpected. Structured output benefits from low temp; creative writing from high temp.
max_tokensLimits output size/cost; too low may truncate output before a natural end.

Topic: ChatOpenAI + Message Types ⭐⭐☆☆☆

# Python
from langchain_openai.chat_models import ChatOpenAI
from langchain_core.messages import HumanMessage
model = ChatOpenAI()
prompt = [HumanMessage("What is the capital of France?")]
model.invoke(prompt)
# AIMessage(content='The capital of France is Paris.')

Four message classes are named explicitly in the chapter:

ClassRoleDescription from text
HumanMessageuser"A message sent from the perspective of the human"
AIMessageassistant"A message sent from the perspective of the AI that the human is interacting with"
SystemMessagesystem"A message setting the instructions the AI should follow"
ChatMessagearbitrary"A message allowing for arbitrary setting of role"

Example combining SystemMessage: instructing the model to "respond to questions with three exclamation marks" → output: AIMessage('Paris!!!'). The chapter notes: "the model obeyed the instruction provided in the SystemMessage even though it wasn't present in the user's question."

Topic: PromptTemplate ⭐⭐☆☆☆

Solves the problem: a hardcoded prompt string can't vary based on user input. PromptTemplate.from_template(...) uses Python f-string syntax — {context}, {question} placeholders filled in via .invoke({...}). Returns a StringPromptValue.

The chapter explicitly states: "both `template` and `model` can be reused many times" — reusability is the whole point.

Topic: ChatPromptTemplate ⭐⭐⭐☆☆

Built with ChatPromptTemplate.from_messages([("system", ...), ("human", ...), ("human", ...)]). Returns a ChatPromptValue wrapping a list of SystemMessage/HumanMessage objects — the correct shape for chat models. Used identically to PromptTemplate: template.invoke({...}) then pass the result to model.invoke(...).

Topic: JSON Output — with_structured_output() ⭐⭐⭐⭐☆

This is presented specifically as a technique for getting JSON out of an LLM (the chapter's broader heading is "Getting Specific Formats out of LLMs").

# Python
class AnswerWithJustification(BaseModel):
    answer: str
    justification: str

llm = ChatOpenAI(model="gpt-3.5-turbo", temperature=0)
structured_llm = llm.with_structured_output(AnswerWithJustification)
structured_llm.invoke("What weighs more, a pound of bricks or a pound of feathers")

Schema defined with Pydantic (Python) or Zod (JS). Per the text, with_structured_output uses the schema for two things:

  1. Converts the schema to a JSONSchema object sent to the LLM (LangChain picks function calling or prompting per-model).
  2. Validates the LLM's returned output against that schema before returning it to you.

Topic: Output Parsers ⭐⭐☆☆☆

For "other machine-readable formats" beyond JSON (CSV, XML, etc.). The chapter's concrete example is CommaSeparatedListOutputParser:

parser = CommaSeparatedListOutputParser()
parser.invoke("apple, banana, cherry")
# ['apple', 'banana', 'cherry']

Two stated functions of output parsers: (1) providing format instructions injected into the prompt, and (2) validating and parsing output into a structured format (removing extraneous text, correcting incomplete output, validating values).

Topic: The Runnable Interface ⭐⭐⭐⭐☆

The chapter states plainly: "all the code examples used so far utilize a similar interface and the invoke() method... All components have the following: a common interface with invoke/batch/stream, built-in utilities for retries, fallbacks, schemas, and runtime configurability, and (in Python) asyncio equivalents for each method."

MethodWhat the text says it does
invoke()"takes a single input and returns a single output"
batch()"takes a list of outputs and returns a list of outputs" (efficiently transforms multiple inputs)
stream()"takes a single input and returns an iterator of parts of the output as they become available"

Note: "In some cases, where the underlying component doesn't support iterative output, there will be a single part containing all output" for stream().

Topic: Imperative Composition ⭐⭐☆☆☆

Definition (verbatim spirit): "just a fancy name for writing the code you're used to writing, composing these components into functions and classes."

# Python — uses the @chain decorator
from langchain_core.runnables import chain

@chain
def chatbot(values):
    prompt = template.invoke(values)
    return model.invoke(prompt)

chatbot.invoke({"question": "Which model providers offer LLMs?"})
// JavaScript — uses RunnableLambda.from
import {RunnableLambda} from '@langchain/core/runnables'
const chatbot = RunnableLambda.from(async values => {
  const prompt = await template.invoke(values)
  return await model.invoke(prompt)
})

Key fact: to add streaming support imperatively, you must manually rewrite the function to yield tokens (Python) or use function*/yield (JS). To add async support in Python, rewrite using async def + ainvoke. The text notes: "asynchronous execution is the only option in JavaScript."

Topic: Declarative Composition (LCEL) ⭐⭐⭐⭐☆

Definition (verbatim spirit): "LCEL is a declarative language for composing LangChain components. LangChain compiles LCEL compositions to an optimized execution plan, with automatic parallelization, streaming, tracing, and async support."

# Python
chatbot = template | model
chatbot.invoke({"question": "Which model providers offer LLMs?"})
// JavaScript — uses .pipe() instead of |
const chatbot = template.pipe(model)

Crucially, the chapter emphasizes: the last line (.invoke/.stream/.batch) is identical whether you used the imperative function or the LCEL chain — and with LCEL you don't need to do anything else to get streaming or async working; it's automatic.

Cheat Sheet

LLM interface:      string in -> string out   (OpenAI class)
Chat interface:     messages in -> message out (ChatOpenAI class)
Roles:               system / user / assistant
Messages:            HumanMessage, AIMessage, SystemMessage, ChatMessage

PromptTemplate       -> single string, {var} placeholders
ChatPromptTemplate    -> list of role-tagged messages

with_structured_output(Schema)  -> validated object (Pydantic/Zod)
CommaSeparatedListOutputParser  -> text -> list

Runnable: invoke() / batch() / stream() (+ retries, fallbacks, schemas, runtime config)
          Python also has asyncio equivalents (ainvoke, abatch, astream)

Imperative: @chain (Python) | RunnableLambda.from (JS) -- manual yield/async needed
Declarative (LCEL): template | model  (Python)  |  template.pipe(model) (JS)
                     -> streaming & async automatic
